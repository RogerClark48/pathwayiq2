WHAT THE APP DOES
-----------------
FutureFinder helps prospective students explore career pathways from GMIoT courses,
and discover courses starting from a career interest. It surfaces GMIoT courses
alongside 1,252 NCS/Prospects job role records, connected by semantic similarity and
Sonnet-generated career pathway narratives.

The live deployment is a single-page web app served by a Python/Flask backend.
No user authentication — all sessions are anonymous and in-memory.

HOW TO RUN IT (V2 — CURRENTLY LIVE)
-------------------------------------
1. Ensure .env exists in the project root:
     ANTHROPIC_API_KEY=...
     VOYAGE_API_KEY=...
     SKILLS_ENGLAND_API_KEY=...   (pipeline only — not needed for the server)

2. Start the server:
     C:\Dev\pathwayiq2\venv\Scripts\python.exe api.py

3. Open http://localhost:5000 in a browser.
   Always open via the server — not directly from the filesystem — to avoid CORS issues.

The frontend is app/index.html, app/style.css, app/app.js — served statically by Flask.

DATA PIPELINE SCRIPTS (scripts/)
----------------------------------
These scripts built the v3 data layer. All are re-run safe (skip already-processed rows
by default; --all overwrites; --id N [N...] targets specific records).

create_courses_db.py
  Creates futurefinder.sqlite from scratch. Loads providers and 82 courses from
  source_data/v3_courselist.xlsx. Run once; re-running recreates the DB.

enrich_courses.py
  Fetch-and-enrich pipeline for courses. For each unenriched course:
    1. Fetches the course URL via requests + BeautifulSoup
    2. Haiku (claude-haiku-4-5-20251001) via forced tool-use: extracts structured fields
       (course_title, campus, ssa_code, qual_type, level, mode, duration, fees,
        overview, content, entry_requirements, progression)
    3. Sonnet (claude-sonnet-4-6) via forced tool-use: generates match_chunk
  Both calls at temperature=0. Stay-within-source prompt rules on both.
  Thin page threshold: 500 chars — skipped with THIN PAGE log.
  Post-processing: apply_defaults() sets mode="FT" if page gave no signal (or
  "Apprenticeship" if qual_type indicates it).

enrich_jobs_chunks.py
  Same fetch-and-enrich pattern for jobs, Sonnet only (no Haiku pass).
  Adds match_chunk to job_roles_asset.db.

build_match_collections.py
  Builds two new Chroma collections from SQLite match_chunks:
    match_courses — 76 course match_chunks
    match_jobs    — 1,215 job match_chunks
  Voyage AI voyage-3.5, output_dimension=1024, input_type="document" for both sides
  (symmetric — match_chunk is a dense document on both sides, not a short query).
  --recreate flag deletes and rebuilds.

build_pathways.py
  Two-pass Sonnet pipeline per course. Writes to course_career_pathways table.
  Pass 1 (Curation, temperature=0):
    Lifts course vector from match_courses Chroma collection.
    Retrieves top 25 candidate jobs from match_jobs collection.
    Sonnet selects a curated cluster (3–15 jobs) with per-job reasoning.
    Prompt asks for full career landscape: entry-level destinations, lateral options,
    longer-term destinations.
  Pass 2 (Narrative, temperature=0.3):
    Sonnet writes full narrative (~500-700 words) and short narrative (~100-120 words).
    Guardrail: "Use your knowledge for context and broader career landscape framing
    where you are confident of the accuracy of any specifics you state. Do not invent
    specifics about this course, these specific jobs, named institutions, qualifications,
    or partnerships. Never assert a specific institution, qualification, partnership,
    employer relationship, or programme that isn't in the source material, even if it
    seems plausible."
  prompt_version field: bump the PROMPT_VERSION constant in the script to invalidate
  the cache and regenerate on next run.

export_enriched.py     → output/enriched_review.txt  (enriched course fields)
export_pathways.py     → output/pathways_review.txt  (narratives + curated job lists)


CHROMA VECTOR STORE (chroma_store/)
-------------------------------------
V3 COLLECTIONS (new — used by build_pathways.py, will be used by v3 api.py):
  match_courses   76 docs   — course match_chunks; doc ID = str(course_id)
  match_jobs      1,215 docs — job match_chunks;   doc ID = str(job_id)
  Both embedded with voyage-3.5, 1024 dims, input_type="document".

V2 COLLECTIONS (untouched — currently used by api.py):
  gmiot_courses           166 docs  — title + overview + what_you_will_learn
  gmiot_jobs            2,432 docs  — title + overview + typical_duties
  gmiot_courses_learning   83 docs  — what_you_will_learn only
  gmiot_jobs_skills     1,216 docs  — skills_required only
  (additional legacy collections also present — not used by api.py)

Cross-collection search pattern: lift a stored embedding vector from one collection
using collection.get(ids=[id], include=["embeddings"]), then pass to
collection.query(query_embeddings=[vec], ...) on the other collection.

IMPORTANT: Stale Chroma HNSW lock files cause 500 errors on startup. If you see
"Nothing found on disk" errors, reboot Windows before debugging code.

CHAT FLOW (unchanged from v2 — documented for the live serving version)
------------------------------------------------------------------------
Two-turn Haiku tool-use pattern:
Turn 1 — specify_searches: Haiku receives query + session context, calls specify_searches
  to declare query_type, searches (query, type, scope, filters), collection_action,
  acknowledgement. Special cases: out_of_scope (no search), explain (direct Haiku answer,
  no retrieval, not a qualifying interaction).
Retrieval: Voyage AI query embedding → Chroma search with optional where clause filters.
Turn 2 — select_results: Haiku picks best candidates, writes one-sentence acknowledgement.
Sessions in-memory (_sessions dict), 30-minute TTL.


ADVISORY CARDS (unchanged from v2)
------------------------------------
System-initiated. Minimum 4 qualifying interactions before first; minimum 5-interaction
gap thereafter. Sonnet generates content using recent session context. Dashed amber border.


JOB PROGRESSION CARDS (v2 — retained in v3)
----------------------------------------------
GET /jobs/<id>/progression
Sonnet generates a narrative + inbound/outbound role lists, cached in job_progression_cache.
Filter: WHERE prompt_version = 4 (bump to invalidate cache).
This artefact answers "what is the career arc of this job?" — distinct from
course_career_pathways which answers "where does this course lead?"

KNOWN ISSUES AND GOTCHAS
-------------------------
- Chroma lock files: stale HNSW locks on Windows cause 500 errors. Reboot Windows
  if you see "Nothing found on disk" errors — do not try to fix in code.

- salary_min/salary_max use 0 as a null sentinel. Do not treat 0 as zero salary.

- 37 jobs have no match_chunk: 35 NCS stub pages (405-char placeholders — nothing to
  enrich) and 2 dead Prospects URLs (ids 857, 968). These are correctly null.

- course_url in futurefinder.sqlite is not unique by design — FT and PT variants of
  the same course can share a URL. Do not add a UNIQUE constraint.

- Course 30 (Tameside HNC Computing, General) is active with no enrichment — sparse
  page, no BeautifulSoup content. No pathway row. Handle gracefully.

- 36 job records have NULL content fields (overview, typical_duties, etc.) in
  job_roles_asset.db. Valid rows — handle gracefully, do not filter out.


DEPLOYING FOR A DIFFERENT INSTITUTION
--------------------------------------
All institution-specific configuration is in institution_config.py. Change only this
file to redeploy for a different institution.

Contains: INSTITUTION_NAME, INSTITUTION_FULL_NAME, INSTITUTION_REGION, COURSES_DB,
PROVIDERS, SSA_MAP, QUAL_FILTER_MAP, SUBJECT_AREAS.

api.py imports all of these at startup. Prompts build their institution-specific
sections from these values at module load time.
